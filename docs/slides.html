The challenge

EPIC Clarity is hard to ingest incrementally

Healthcare organizations struggle with large, complex Clarity databases where database-level CDC is rarely an option — leading to slow full-table reloads and stale analytics

Massive table sizes

Clarity spans thousands of tables and the largest hold billions of rows, making full extracts on every refresh slow and expensive.

Database CDC is off-limits

SQL Server CDC or Change Tracking usually can't be enabled on Clarity under Epic support policies — teams must engineer their own incremental strategy or resort to full reloads.

Stale data

Full reloads of large tables take hours, so downstream analytics and AI models fall further behind Clarity's own nightly refresh.

The solution

WaterSync turns CSA tables into an incremental pipeline

A Databricks accelerator that leverages EPIC's Change Sync Administration (CSA) tables to detect and extract only changed records
  • CSA-driven change detection — uses EPIC's CSA (Change Sync Administration) tables, which record the key, a change sequence, and a delete flag for every changed Clarity row
  • Bronze to Silver in Delta — only changed rows are appended to a Bronze staging table, then a Lakeflow Declarative Pipeline applies them with AUTO CDC to a Silver SCD Type 2 table, deletes included
  • Metadata-driven — table mappings live in a Delta config table and watermarks in a state table, managed from the WaterSync Control Plane app
  • Medallion-ready — Bronze and Silver tables land in Unity Catalog, ready for Gold transformations downstream
  • Source available — published on GitHub under the Databricks License, with pluggable ingestion workers you can extend

Key concept

CSA tables are EPIC's built-in change tracking mechanism

Change Sync Administration tables record every changed row with a monotonically increasing extract key — WaterSync uses that key as its incremental watermark

How CSA tables work

For each CSA-enabled Clarity table (e.g., PAT_ENC), EPIC maintains a paired table in the EPIC_UTIL schema (e.g., CSA_PAT_ENC) that holds:

  • Primary key columns of the changed row
  • _TIMESTAMP_EXTRACT_KEY — monotonically increasing change sequence
  • _UPDATE_DT and _IS_DELETED — change time and delete flag
  • Enabled per table — CSA pairs are switched on together with your Epic team

Why CSA is ideal for incremental ingestion

  • No database CDC required — CSA is populated by EPIC, on SQL Server or Oracle Clarity
  • Sequence-based watermarking — read only rows whose extract key is above the last sync
  • Captures deletes — _IS_DELETED closes out removed rows that timestamp polling misses
  • Lighter source reads — only changed keys are joined back to the base table, no full scans

Under the hood

Four-step incremental sync cycle runs on every execution

Each pipeline run queries only the delta of changes since the last successful watermark, minimizing load on the source system
1

Read watermark

Read the last stored CSA extract key from the watermark table in Unity Catalog. On the first run there is none, so the table is loaded in full.

2

Check CSA table

Read the current max _TIMESTAMP_EXTRACT_KEY as the upper bound. If it has not moved past the watermark, the table is skipped.

3

Extract & apply

Join CSA rows in the window to the base Clarity table and append them to Bronze staging. A Lakeflow pipeline then applies them with AUTO CDC to the Silver SCD Type 2 table, deletes included.

4

Advance watermark

On success, store the upper-bound extract key as the new watermark. The next run will pick up only subsequent changes.

Configuration

A Delta config table maps Clarity tables to Delta targets

Each row defines the source connection, the table, its keys, and the Delta targets — the CSA table and watermark are derived automatically, and the Control Plane app writes the rows for you

-- register a Clarity table for CSA ingestion
INSERT INTO watersync.jdbc_ingestion_config
  (ingestion_group, source_table_name,
    target_table_fqn, staging_table_fqn,

VALUES
  ('clarity', 'dbo.PAT_ENC',
    'hls.silver_clarity.pat_enc',
    'hls.bronze_clarity.staging_pat_enc',
    'incremental', 'PAT_ENC_CSN_ID',
    true, 'clarity_conn', true);

-- CSA table derived: EPIC_UTIL.CSA_PAT_ENC
